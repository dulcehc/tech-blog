# Publishing guide

How to deploy CDMX Tech Journal, track interest, and manage content in git.

## Where to publish

Deploy only the **built static site** (`site/dist/`), not the full monorepo.

| Host | Cost | Custom domain | Notes |
|------|------|---------------|-------|
| **[Cloudflare Pages](https://pages.cloudflare.com/)** | Free | Yes (~$10/yr domain) | Fast, simple git deploy |
| **[Netlify](https://www.netlify.com/)** | Free tier | Yes | Same workflow |
| **[Vercel](https://vercel.com/)** | Free tier | Yes | Same workflow |

**Recommended:** Cloudflare Pages + domain from Cloudflare or Namecheap.

### Build settings

| Setting | Value |
|---------|-------|
| Root directory | `site` |
| Build command | `cd .. && pnpm install --frozen-lockfile && pnpm site:publish` |
| Output directory | `dist` |

Or build locally and upload `site/dist/` — no CI needed for V1.

### Domain

You need a domain (~$10–15/year). Ideas:

- `cdmxtechjournal.com`
- `mxcity.tech`
- `cdmxtech.mx`

Point DNS to your host after purchase. Set `PUBLIC_SITE_URL` in `site/.env` to match.

## Mixpanel (track if it's worth continuing)

1. Create a free [Mixpanel](https://mixpanel.com/) project
2. Copy the **project token**
3. Create `site/.env`:

```bash
PUBLIC_MIXPANEL_TOKEN=your_token_here
PUBLIC_SITE_URL=https://yourdomain.com
```

4. Rebuild and deploy

Leave `PUBLIC_MIXPANEL_TOKEN` unset to disable analytics. Before enabling it,
publish a privacy notice and review Mixpanel's data collection and consent
requirements for your audience.

**What to watch (first 2–4 weeks):**

| Signal | Healthy | Maybe shut down |
|--------|---------|-----------------|
| Unique visitors/week | 20+ from shares | < 5 after promoting |
| Avg session | > 1 page | Bounce on homepage only |
| Return visits | Any | Zero after launch week |

Mixpanel free tier is enough for this experiment.

## What lives in the repo vs deploy

```
┌─────────────────────────────────────────────────────────┐
│  GIT REPO (private or public)                           │
│                                                         │
│  events/                                                │
│    ├── event.yaml          ← metadata, gallery list     │
│    ├── sources/notes.md    ← your fragments             │
│    ├── sources/slides/     ← RAW photos (gitignored)    │
│    ├── published/post.mdx  ← approved write-up          │
│    └── published/gallery/  ← curated photos (optional)  │
│                                                         │
│  packages/chronicle/       ← engine                     │
│  site/                     ← Astro site                 │
└─────────────────────────────────────────────────────────┘
                          │
                   pnpm build
                          ▼
┌─────────────────────────────────────────────────────────┐
│  DEPLOYED (site/dist/)                                  │
│                                                         │
│  Only published HTML + selected gallery images          │
│  No raw slides, no drafts, no notes                     │
└─────────────────────────────────────────────────────────┘
```

### Git rules

| Path | In git? | Why |
|------|---------|-----|
| `event.yaml` | Yes | Source of truth |
| `published/post.mdx` | Yes | Approved content |
| `published/gallery/*` | Yes (selected) | Survives CI deploy |
| `sources/notes.md` | Yes | Small text |
| `sources/slides/*` | **No** | Large raw dumps |
| `drafts/*` | **No** | Working files |
| `site/src/content/events/*` | **No** | Generated by sync |

### Gallery: only selected photos publish

List photos in `event.yaml`:

```yaml
gallery:
  - file: published/gallery/womencon-swag.jpg
    caption: "WomenCon shirt, badge, pins, and lanyard"
```

Sync copies **only** listed files to the site. Everything else stays private.

## Slide photos + summaries — effort estimate

### V1 (now): Cursor-assisted, manual curation

| Step | Time per event | Who |
|------|----------------|-----|
| Drop slide photos in `sources/slides/` | 2 min | You |
| Add 2–5 photos to `gallery` in event.yaml | 3 min | You |
| Ask Cursor to read slides + notes, draft summary | 5–10 min | AI + review |
| Edit `published/post.mdx`, set `summary` | 10–15 min | You |

**Total: ~20–30 min per event** if you have photos and bullet notes.

For 8 events from Jul–Aug: **~3–4 hours** spread over a few sessions.

### What AI can read today

In Cursor, attach slide images from `sources/slides/` and ask:

> Read these slides and my notes. Write a community spotlight: topics, communities, people to follow. Not about me.

Cursor reads images directly — no extra tooling needed.

### V2 (future, optional)

A `chronicle summarize` command with a vision API could batch-read slides. Not built yet — only worth it if you're publishing weekly.

## Quick publish checklist

```bash
pnpm chronicle new "WomenCon 2026" --series cdmx-tech-summer-2026 --date 2026-07-25
# add notes + slides, edit event.yaml gallery + spotlight
pnpm chronicle validate
# set status: published
pnpm build
# deploy site/dist/
```
